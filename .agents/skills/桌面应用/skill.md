# 桌面应用 —— AI 驱动的桌面应用生成器

## 触发条件

当用户提出以下任一需求时调用此 Skill：
- "帮我写一个桌面应用" / "生成一个桌面应用" / "创建一个桌面程序"
- "做一个桌面工具" / "写个桌面软件" / "开发桌面应用"
- "我需要一个 XXX 的桌面版" / "帮我做一个桌面端 XXX"
- 用户描述了功能需求并明确提到"桌面"、"客户端"、"Window/Mac/Linux 应用"
- "build a desktop app" / "create a desktop application"

## 核心能力

1. **智能技术选型**：根据需求自动推荐最合适的技术栈（Electron / Tauri / Python）
2. **方案先行**：先生成完整的技术方案和项目结构，用户确认后再编写代码
3. **全类型覆盖**：支持工具类、数据面板、硬件交互、媒体处理四类桌面应用
4. **可运行交付**：生成的项目代码包含完整的构建配置，可直接 `npm install && npm start` 运行
5. **跨平台优先**：默认生成 Windows/Mac/Linux 三平台兼容代码

## 执行步骤

### Step 1: 需求分析

从用户描述中提取以下信息，**任一字段缺失则主动提问**：

```
【应用需求画像】
功能描述：<这个应用要做什么？一句话概括>
应用类型：工具类 / 数据面板 / 硬件交互 / 媒体处理
目标平台：Windows / Mac / Linux（默认全平台）
数据来源：本地文件 / 用户输入 / API 接口 / 硬件设备
是否需要持久化存储：是 / 否
是否需要联网：是 / 否
```

> **提问原则**：不要一口气问完所有问题，先让用户描述需求，缺失的字段再逐个补充。

### Step 2: 技术选型

根据 `references/rules.md` 中的「技术选型决策树」进行选型，并向用户说明推荐理由：

```
【技术选型推荐】
推荐技术栈：<Electron / Tauri / Python + GUI框架>
选型理由：
  1. <理由一>
  2. <理由二>
  3. <理由三>
备选方案：<替代技术栈及适用场景>
```

> **注意**：如果用户已有技术偏好，直接采用用户的选择，跳过此步。

### Step 3: 方案设计

生成以下结构化的方案文档，**等待用户确认后再进入 Step 4**：

```markdown
## 项目方案

### 基本信息
- 项目名称：<kebab-case 名称>
- 技术栈：<框架名 + 版本>
- 包管理器：npm / yarn / pnpm（推荐 npm）

### 项目目录结构
<项目名>/
├── package.json          # 项目配置与依赖
├── src/
│   ├── main/             # 主进程（Electron/Tauri 后端）
│   │   └── index.js      # 入口文件
│   ├── renderer/         # 渲染进程（前端 UI）
│   │   ├── index.html    # 主页面
│   │   ├── style.css     # 样式文件
│   │   └── app.js        # 前端逻辑
│   └── preload/          # 预加载脚本（仅 Electron）
│       └── index.js
├── assets/               # 静态资源（图标等）
└── README.md

### 核心功能模块
1. <模块名>：<功能说明>
2. <模块名>：<功能说明>
...

### 依赖清单
- 运行时依赖：<列表>
- 开发依赖：<列表>

### 风险与注意事项
- <列出可能的技术难点或需要用户注意的事项>
```

### Step 4: 代码生成

用户确认方案后，按以下顺序生成文件：

1. `package.json` —— 项目配置
2. 主进程入口文件 —— 窗口创建、系统托盘、菜单等
3. 渲染进程文件 —— HTML 结构 + CSS 样式 + JS 交互逻辑
4. 预加载脚本（Electron）或 Rust 后端配置（Tauri）
5. `README.md` —— 运行说明

**文件生成规则**：
- 每次生成一个完整文件，用 `Write` 工具写入
- 生成顺序按依赖关系（先配置，后功能）
- 每个文件写入后给出简短的说明注释
- UI 默认采用简洁现代风格，兼容暗色模式

### Step 5: 运行验证

所有文件生成完毕后，输出运行指引：

```markdown
## 🚀 运行指引

### 1. 安装依赖
```bash
cd <项目目录>
npm install
```

### 2. 启动应用
```bash
npm start
```

### 3. 构建分发
```bash
npm run build
```
```

## 关键规则

### 不可违反的规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | 方案必须先确认 | Step 3 方案必须等待用户明确同意后，才能进入代码生成 |
| 2 | 技术选型有据 | 每次选型必须引用 `references/rules.md` 中的决策规则 |
| 3 | 代码必须可运行 | 生成的 `package.json` 必须包含完整的 scripts 和 dependencies |
| 4 | 不省略错误处理 | 所有文件 I/O、网络请求、IPC 调用必须有 try-catch |
| 5 | 安全第一 | Electron 项目必须启用 `contextIsolation: true` 和 `nodeIntegration: false` |
| 6 | 使用简体中文 | 所有注释、README、UI 文本使用简体中文 |

### 推荐遵守的规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | 代码注释率 ≥20% | 关键函数和模块需中文注释 |
| 2 | 单一入口 | 渲染进程逻辑集中在 `app.js`，避免碎片化 |
| 3 | 响应式布局 | CSS 使用 flex/grid，窗口缩放不乱版 |
| 4 | 优先用户目录 | 数据持久化优先使用 `app.getPath('userData')` |

## 技术栈快查

详细选型规则见 `references/rules.md`，以下是快速参考：

| 场景 | 推荐技术栈 | 包体积 | 开发效率 |
|------|-----------|--------|---------|
| 简单工具（计算器、Todo） | Tauri | ~5MB | ⭐⭐⭐ |
| 数据面板/仪表盘 | Electron | ~150MB | ⭐⭐⭐⭐⭐ |
| 硬件交互（摄像头、蓝牙） | Electron | ~150MB | ⭐⭐⭐⭐ |
| 媒体处理（图片/视频） | Electron | ~150MB | ⭐⭐⭐⭐ |
| 轻量级 CLI 转 GUI | Tauri | ~5MB | ⭐⭐⭐ |
| 科学计算/数据图表 | Python + PyQt6 | ~80MB | ⭐⭐⭐ |
| 快速原型验证 | Python + tkinter | ~15MB | ⭐⭐⭐⭐⭐ |
| 企业内部工具 | Electron | ~150MB | ⭐⭐⭐⭐⭐ |

## 注意事项

1. **Electron 体积较大**：默认 ~150MB，首次 `npm install` 需下载 Electron 二进制文件（约 2-5 分钟）
2. **Tauri 需要 Rust 环境**：用户机器需预装 Rust（`rustup`），否则引导用户安装
3. **Python GUI 跨平台兼容性**：tkinter 在 Windows 上默认随 Python 安装，Mac/Linux 可能需要额外安装 `python3-tk`
4. **Node.js 版本要求**：Electron 项目建议 Node.js ≥18，Tauri 项目建议 Node.js ≥16
5. **管理员权限**：某些硬件交互功能可能需要管理员权限，生成代码时需添加权限检测
