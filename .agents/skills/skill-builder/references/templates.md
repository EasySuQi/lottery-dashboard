# Skill 编写参考手册

> 本文档是 Skill Builder 的内部参考，记录 Claude Code Skill 系统的约定和最佳实践。
> 由 skill-builder 在生成新 Skill 时引用其中模板。

---

## 1. Skill 文件标准骨架

```markdown
# <Skill 中文名称>

## 触发条件 (必填)

当用户提出以下任一需求时调用此 Skill：
- <触发场景 1>
- <触发场景 2>
- <触发场景 3>

> 如有容易混淆的场景，加注说明区分方式。

## 核心能力 (必填)

1. **能力1**：<一句话描述>
2. **能力2**：<一句话描述>
3. **能力3**：<一句话描述>

## 执行步骤 (必填)

### Step 1: <步骤名>
<!-- 具体指令 -->

### Step 2: <步骤名>
<!-- 具体指令 -->

### Step 3: <步骤名>
<!-- 具体指令，包含输出格式要求 -->

## 关键规则（不可违反）(按需)

### <规则分类1>
| 规则 | 说明 |
|------|------|
| 规则名 | 具体值/描述 |

## 注意事项 (推荐)

- <注意事项1>
- <注意事项2>

## 免责声明 (按需)

> <免责文字>
```

## 2. 常见 Skill 类型模板

### 类型 A: 数据驱动分析 Skill

**特征**: 获取外部数据 → 统计分析 → 输出结果

**文件结构**:
```
<名称>/
├── skill.md          # 触发词 + 执行步骤 + 规则速查
└── references/
    ├── rules.md      # 完整规则手册（数据格式、阈值定义、约束条件）
    └── analyzer.js   # 分析引擎（可独立运行的 Node.js 脚本）
```

**skill.md 必须包含**:
- API 的 curl 命令（完整的 URL + Headers）
- 返回数据的字段说明
- 数据注入方式（如何填入 analyzer 脚本）
- 预期的 4 段输出格式（分区/冷热/约束/成品）

**analyzer.js 必须**:
- 顶部有数据注入区（`const draws = []; // 由 Skill 填充`）
- 所有分析逻辑在一个 `main()` 函数中
- `node --check` 语法验证通过
- 输出直接打印到 stdout（由 Claude 读取后格式化呈现）

### 类型 B: 流程指引 Skill

**特征**: 纯文本流程，无外部数据，指导 AI 完成一套固定步骤

**文件结构**:
```
<名称>/
└── skill.md          # 单文件，所有步骤内联
```

**skill.md 必须包含**:
- 每个 Step 的决策树（if/else 分支）
- 输出模板（Markdown 表格或代码块格式）
- 常见场景的预设回复

### 类型 C: 代码生成 Skill

**特征**: 根据输入模板生成代码文件

**文件结构**:
```
<名称>/
├── skill.md          # 触发词 + 模板变量 + 生成规则
└── references/
    └── templates/    # 代码模板文件
```

## 3. 触发词设计原则

| 原则 | 说明 | 好例子 | 坏例子 |
|------|------|--------|--------|
| 关键词+句式 | 同时覆盖关键词和自然语言 | "双色球" / "分析福彩数据" | 仅 "彩票"（太宽泛） |
| 防误触 | 加限定条件避免与日常对话混淆 | "写一个 Skill" + 上下文判断 | "帮我"（太通用） |
| 中文优先 | 中文触发词对准中文用户习惯 | "帮我生成号码" | "generate number" |
| 3-5 个场景 | 覆盖不同表达方式 | 见福彩/体彩 Skill | 只有 1 个场景 |

## 4. 规则编写原则

### 4.1 冷热/阈值类规则

```markdown
### <分类>冷热阈值（基于 <窗口大小>）

| 等级 | 出现次数 | 标签 | 占比参考 |
|------|---------|------|---------|
| 🔥 热号 | ≥ N 次 | HOT | 约前 X% |
| ● 温号 | M1-M2 次 | WARM | 约中间 Y% |
| ❄️ 冷号 | 1 次 | COLD | 约后 Z% |
| 🧊 极冷 | 0 次 | ICE | — |

> 阈值校验：说明理论期望值及阈值选取理由。
```

### 4.2 约束/禁止类规则

```markdown
| 规则 | 值/条件 | 严重性 |
|------|---------|--------|
| 规则名 | 具体数值或条件 | ❌禁止 / ⚠️不推荐 / ✅推荐 |
```

### 4.3 分区/分类类规则

```markdown
### N区定义

一区: <范围>  (共 N1 个号码)
二区: <范围>  (共 N2 个号码)
三区: <范围>  (共 N3 个号码)
```

## 5. 校验脚本

内置于 skill-builder 的质量检查逻辑：

```
1. skill.md 存在?
2. skill.md 包含 "触发条件" 章节?
3. skill.md 包含 "执行步骤" 章节?
4. skill.md 包含表格? (有规则时)
5. 触发场景 ≥ 3 个?
6. 执行步骤 ≥ 2 个 Step?
7. 无模糊词 ("酌情", "根据需要", "适当")?
8. references/ 下的 .js 语法正确?
9. rules.md 与 skill.md 阈值一致?
10. 文件名不含空格/特殊字符?
```

## 6. 文件命名约定

| 文件/目录 | 约定 | 示例 |
|----------|------|------|
| Skill 目录 | 中文短名, ≤8 字 | `福彩`, `skill-builder` |
| skill.md | 固定文件名 | `skill.md` |
| rules.md | 固定文件名 | `references/rules.md` |
| 引擎脚本 | 英文短名, 下划线分隔 | `ssq_analyzer.js`, `dlt_analyzer.js` |
